## What changed

- **Highlighting is wired in** (`content.rs`). A fence is folded, trailing
  newlines are dropped (the oracle `rstrip`s pygments' output), and
  `crate::highlight::spans` (WP-3.3a/5.5d) lexes the folded text. `code_inks`
  turns spans into `(bytes, ink)` runs: a class resolves through `CODE_INKS`,
  the 41 classes / 7 inks of `weasyprint-a5.css:961-968`, and `o`, `p` and every
  unlisted class resolve to `none` (inherit). A language pygments would highlight
  with a lexer mag lacks is refused (`Err`), not silently plain. The emitter writes
  `#doc-code(lang:, inks:, <raw block>)`. The raw literal stays as the argument, so
  the WP-2.1 projection and its verbatim runs read it unchanged. Typst's lexer
  does not dedent it because the closing fence is in column 0.
- **Template code panel.** `code-runs` slices `body.text` by the byte runs and
  asserts that they cover it. The old path displayed the raw element, whose default
  show rule set it at 0.8em in a fallback face (about 6pt instead of 7.5pt). The
  panel is 7.5pt/1.3 Geist Mono, padded 3mm. `pre`'s UA margin is 1em (7.5pt), not
  5.4pt (`html5_ua.css:39`). `ruled` now puts the fill on an outer block, so the
  pale fill starts under the 1.5pt border as CSS `background` does (border-box).
  Before, it started at the border's centre, 0.75pt right.
- **Extracts.** A code extract is `code-panel(collapse: true)`: each line is trimmed
  and its whitespace runs collapsed, as `.extract pre { white-space: normal }` does
  over the adapter's `<br>`-joined lines. The label's line box is the inherited
  `html` 13pt, not 6.8pt (3.1pt above and 3.1pt below its baseline, measured).
- **Reference list.** Set on `edges(7.2, 9.4)` and moved down by `DATUM - 4.7 -
  0.3505*7.2` (2.781pt, the stylesheet's own `translateY`). `pinned(9.4)` gave a
  10.0pt pitch: typst clamps a bottom edge above the baseline, so the edge
  0.6046pt above was dropped. The reference style now applies only to unordered
  lists: `ul[data-reference-list]` does not match `ol`, so an ordered list under
  "References" keeps the body style. This was a latent typst bug.
- **Plain-opener source code.** `article_head` reads the committed matrix for a
  plain article with a `source_url`, refusing like the oracle when none is
  committed. It passes the matrix to `#byline(code:)` and `#author-note(code:)`.
  The template places `qr-symbol(rows, side: 55.5pt)` at `dx = -quiet`, `dy =
  -7.4 * 1490/2048 - quiet` off the byline baseline, which is
  `_opener_source_codes`' rule (`weasyprint_adapter.py:2041-2073`). It insets the
  byline and note by `55.5 - 2*quiet + 14.175` (`_credit_column_inset`). The code is
  not linked, as in the oracle (the plain `<img>` sits in the header, outside any
  `<a>`). The plain byline prefix is now plain 7.4pt INK. The `.byline-prefix`
  rule is scoped to illustrated openers, and the old typst stub set it at 6.2pt
  violet. Byline letter-spacing compression is **not** ported: a byline past the
  credit column fails an `assert` naming that.
- **/Lang.** `#set text(lang:, region:)` from `edition.locale` (the oracle's
  `<html lang>`), split at `-`/`_`.
- **Fixtures.** 902 has four illustrated articles. Article 1 carries rust,
  typescript and bash fences, a begin/end code extract, `## References` with an
  unordered list (a three-line entry, so line 2 runs the 312.0256pt measure) and an
  ordered list. 903 has the same code article plus three plain openers, each with
  a 55.5pt code. `fixture-source-c` carries every fence and the extract verbatim.
  900 gains `source-codes/`, now required for its plain opener. Every
  `source-codes/` was generated by `tools/sourcecodes.py generate` with `ROOT`
  pointed at the corpus, and `check` reports that it reproduces byte for byte.
  `expected-902.json` and `expected-903.json` come from `typeset_oracle.py
  project`. Plate art 4-6 is flat colour and openers 2-4 are the mirror, flip and
  invert of `opener.png`, because the adapter refuses repeated filler art.
- `block`/`section` in `content.rs` became `markup_block`/`section_piece`. They
  now return `Result`, which made their signatures collide with `web/semantic.rs`
  under `rust_helpers`.

`codeink.py` (scratch) finds every filled rect of `rgb(95.5% 94.5% 97.5%)` wider than
200pt on each page. It collects the chars whose origin lies inside, drops
whitespace chars (WeasyPrint writes no space glyphs, typst does), sorts by line
then x, and merges same-line, same-u8-fill neighbours into runs. It reports each
box's rect delta and whether the run lists are equal.

## Residuals and defects found (owners)

- **Plain opener not ported (mine by Owns, measured gap).** The oracle fits the
  title (`_fitted_title_box`), justifies the label (`space-between`), pins the
  field heights (`_pin_opener_fields`) and sets the byline-to-note gap. On 903
  page 4 the typst note sits 2.69pt lower relative to the byline. The typst plain
  opener is still the pre-WP stub, so 903's opener pages and their flow differ. The
  byline's letter-spacing compression is also unported and refuses loudly. This
  needs its own WP. The code square, inset and prefix are correct relative to the
  byline.
- **Closing plates (WP-3.4).** (a) The oracle's `_place_closing_plates` puts
  slot 0 at `articles[-1]`, which is after the LAST article. Typst's `plates-before`
  puts it before article 1. (b) Typst prints every configured plate, while the
  oracle prints `_signature_closing_plates` many and refuses too few. The fixtures
  sidestep both (902: 4 articles, 5 plates; 903: 6).
- **Contents with four entries (WP-3.5).** Page 3 has dy 98.25 and an annotation
  mismatch on both fixtures. The 9-entry 010 contents passes.
- **Heading first after an illustrated opener (WP-3.2/3.7).** The oracle keeps
  the h2's 20.4pt margin after the forced break, and typst drops it (dy 20.4). The
  fixtures open each body with a paragraph.
- **E tier (WP-3.7).** WeasyPrint paints a page's in-flow backgrounds (the `pre`
  fill and rule) before its text, and a positioned `li::before` disc after it. Typst
  paints in tree order. The pairing of shows across W's per-span runs gives the
  glyph-position tier's 203pt "worst" on 902 page 6, although G there is 0.001pt.
- **Render critic (WP-2.0b/5.3g).** pypdf reads a right-hand code line with a
  colour change next to a space differently on the imposed booklet side. That
  fails `booklet-page-order` and blocks the oracle render. The fixture's code is
  worded around it.
- **Comparator:** `tier S code_blocks` is still `not_evaluated` (WP-0.2b). The
  code-box claims above rest on `codeink.py`, the colour tier and the tests.
- `meta/verification/baseline.json` is not mine. `template.typ` is a renderer
  file, so the staged digest moves with this commit.

## What is and is not proven

- Proven on fixture 902: code boxes carry the oracle's text runs and inks glyph for
  glyph (colour tier pass, codeink equal, and a test with a control). Box rects are
  within 0.03pt and every line within 0.001pt. The extract and reference list
  match within 0.002pt. The typst inputs equal the WeasyPrint HTML's pre runs byte
  for byte. The BEFORE legs fail each of these, which is the positive control.
- Proven on 010: nothing moved. The PDFs are identical, the projection is identical,
  and the ratchet has 0 regressions.
- Equality caveats (rule 4): the inks are the stylesheet's own values, pinned by the
  CSS-parsing test, not copied from a render. The 2.781pt reference shift, the
  7.5pt code margins and the 13pt label line box are CSS semantics derived from the
  sources cited above.
- Not proven: code blocks wider than the measure (pre-wrap and `overflow-wrap:
  anywhere` against typst's breaking), tabs, blank lines inside a fence, a fence
  split across pages, code inside lists or quotes, and quote-style extracts against
  the oracle (900 has one, but 900 is not renderable by the oracle). Spanish
  output beyond `/Lang`, and the plain opener as a whole, are not proven either.
