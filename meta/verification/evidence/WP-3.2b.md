## What changed

- **Item 3 was mis-attributed.** WP-3.5 read the colour first difference at paint
  1 as the QR/credit block. The comparator drops leading white fills; paint 0 on
  both legs was the orange tick. Paint 1 was the opener art: the oracle paints the
  orange offset there, typst painted `opener-art()`'s white frame with a stroke.
  The QR block was simply missing from the typst leg.
- **Oracle paint order, reproduced** (`template.typ` `opener-page`). WeasyPrint
  paints in-flow backgrounds, then in-flow text, then positioned boxes in tree
  order, then the `z-index: 1` image. Read from `reader.pdf` page 7: tick; label,
  title and standfirst text; orange offset (absolute, z 0); `.opener-meta`
  (relative) border-bottom rule, byline and note text, QR; image border; image.
  The opener is now a fixed-height block whose parts are `place`d at offsets
  computed from `measure` (label, title, credit grid, standfirst) in that order.
  The vertical geometry is the same sum the old flow used.
- **Item 1, opener rasters.** The emitter passes the art to `#piece(art: (path,
  pixels))`. `covered()` implements `object-fit: cover; object-position: 49% 47%`
  on the 343.2 x 198.2pt content box inside the 2.4pt border, clipped. On page 7
  it gives the oracle's image matrix and clip exactly (`[34320,0,0,19968,3890,36389]`,
  same rgba sha256).
- **Item 2, the border** is a PAPER-INK even-odd fill of two rectangles, inner
  first, as WeasyPrint writes it (`re re f*`), with `curve.close(mode:
  "straight")` (the default smooth close emits a degenerate cubic).
- **The QR code.** `source_code()` in `content.rs` reads the committed
  `source-codes/codes.json` print matrix for the article's payload, refusing like
  the oracle when no printable code is committed. `qr-symbol()` draws the white
  41pt square, then one INK path of horizontal runs with the 4-module quiet zone.
  The oracle's data-URI SVG rounds every run start, width and the module to 4
  decimals and builds the end by relative `h`. The typst side rounds the same way.
  Without that, 9 coordinates on pages 40 and 46 were off by one 0.01pt quantum.
- **Byline line box** (`credit-column`). The 6.2pt `.byline-prefix` inline box
  with the inherited 8.5pt line-height hangs `(7.4 - 6.2) * HALF-SANS =
  0.43652pt` below the 7.4pt strut, so the CSS line box grows by that much. The
  grid centres the credit against the 41pt code, which lifts the byline 0.218pt.
  This is derived from the inline box model, not fitted. It was the 0.22pt G drift
  on the openers. The byline's bottom edge is now the prefix's.
- **Item 4, the document.** `#set document(title: "<publication>: <title>")`
  heads `main.typ`. The projection walker treats `SetRule` as code (it carries no
  reader text). `bookmark(level, body)` puts a hidden, bookmarked, unoutlined
  `heading` beside the contents label, each piece title (plain and illustrated)
  and each `doc-heading`. typst-pdf nests them as WeasyPrint's UA `bookmark-level`
  does, so a level-3 heading under an h1 is depth 2.
- **Fixture 901** gains `source-codes/` generated by `tools/sourcecodes.py`'s own
  `generate` with `ROOT` pointed at the corpus. `check` on the result reports "2
  files reproduce byte-for-byte".

## What is and is not proven

- Proven on 010 en: every opener page paints the oracle's colours in the oracle's
  order (Tier S colour 0 pages). 8 of 9 opener pages have E display lists equal to
  the oracle's element by element: art matrix, clip, ring, QR path and text. Page
  4 differs only at the inline-code chip. G max dy 0.006. Title, lang and the
  51-entry outline equal the post-WP-0.0e oracle in order, depth and page.
  56 = 56, the WP-2.1 projection is byte-identical, and the staged ratchet passes
  with 0 regressions.
- Rule 4, equality caveats. The QR coordinates copy the oracle's 4-decimal SVG
  rounding: harmless, sub-quantum, and not a correctness claim. The byline line
  box growth is correct CSS behaviour, and the typst side now has it too.
- Not proven: plain (non-illustrated) openers' codes. The oracle places an
  absolute code at the byline baseline there. The emitter passes `code: none`
  for them and the template draws nothing, as before. 010 has no plain opener.
  Also not proven: Spanish, whose `/Lang` typst would still write as `en`
  because the template sets no `text.lang`.
