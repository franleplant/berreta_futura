Twenty-two thousand five hundred and eighty. That's how many GPT-2 (2019) models fit inside KimiK3 (2026), 124 million parameters against 2.8 trillion. Whether that gap is just scale is worth asking, and it isn't: at nearly every step along the way, the extra parameters bought the model something it couldn't do before.

GPT-2 is a decoder-only transformer: token and position embeddings feed a stack of attention-and-MLP blocks, and a language-model head turns the final hidden state into vocabulary logits, 124 million parameters in total. Only the logits at the last position matter for producing the next token, but a decoder recomputes a representation for every position at every step regardless, so without a cache each new token would force the model to redo its entire history. The fix is to store every earlier token's key and value vectors instead of recomputing them: the KV cache. It removes the redundant work, but it only ever grows, one more entry every step, until at scale it becomes a memory-bandwidth bottleneck of its own.

Linear attention attacks that growth directly. Softmax attention pairs a query against every key through an exponential that has to see both vectors at once. Linear attention applies a feature map, ELU+1, to queries and keys separately, which makes the product re-associable: the running sum of keys and values folds into one fixed-size matrix instead of a list that gets longer every step. The state stops growing. It also stops being exact: ELU+1 approximates the softmax kernel less faithfully, and how much accuracy that costs depends on the architecture and the workload.

The paper's O(N²) framing threw me off. It's not true that "the cost per time-step for transformers scales with the square of the current sequence length." That's what Flash Attention fixes... then I saw that it was released in 2020. At the time, FlashAttention didn't exist and reference implementations recomputed the whole history at every step, so the framing matched the code people actually ran rather than the mechanism itself.

## DeltaNet

A fixed-size cache buys speed at a cost: nothing ever leaves it. Every new key-value pair folds into the same matrix as everything before it, so once the state holds more associations than it has room for, a fact from token one and a fact from token one thousand start to blur together, what Schlag's paper on Fast Weight Programmers calls an "overcapacity regime," where "the purely additive instruction may be inappropriate" and endlessly adding new associations "inevitably will reach a limit." DeltaNet's fix is to stop just adding. Before writing a new value under a key, it reads what's already stored there, subtracts that from the value it wants written, and writes back only the difference, scaled by a learned strength that sets how hard to overwrite. A key gets replaced instead of blurred.

The replacement is precise, but computing it directly is sequential: each token's correction depends on the full state left by the token before it, one at a time, the opposite of what a GPU wants. This is the hardest part of the whole lineage to work through. It took the author about seven hours to develop a working understanding of it, so I will build the explanation from the implementation. The fix reparameterizes the recurrence so all the corrections inside a chunk of tokens can be solved for at once and folded into the state with one matrix multiply per chunk: ordinary masked attention inside a chunk, the recurrent update across chunks. Make the chunk as long as the sequence and you've recovered plain O(N²) attention; make it one token long and you're back to linear attention. Every size in between trades a fixed per-token cost for a per-chunk cost that grows with the chunk, and the smallest chunk wins on paper. In practice, chunks of 64 or 128 tokens win in wall-clock time instead, because that's the size a GPU's matrix-multiply hardware is built to run efficiently.

## Gated DeltaNet and Kimi Linear

Precise replacement solves interference, not forgetting. The delta rule can overwrite one association it has a key for; it can't clear several at once or decay the cache generally, the way you'd want at a context switch. Mamba's answer is a single decay factor applied to the whole cache before every write, uniform across every association whether or not the model still needs it. Gated DeltaNet keeps the delta rule's precision and adds Mamba's decay as a second control, a factor that behaves like the pure delta rule at one and clears the cache at zero, so precise replacement of one fact and general decay of everything stop trading off against each other.

Kimi Linear's contribution is to stop decaying the whole state by one number. Instead of a single scalar controlling how fast everything fades, it learns a separate decay rate for each channel, so a layer can hold one association steady while letting another fade. Under the authors' own controlled comparisons, the resulting architecture beat full attention on quality while decoding up to six times faster. It layers that per-channel gating onto the DeltaNet transformer through three changes: periodic layers of full Multi-head Latent Attention interleaved among the linear-attention layers, a Mixture-of-Experts in place of the MLP, and the added capacity spent specifically on that per-channel decay.

## KimiK3

KimiK3's backbone is Kimi Linear at far larger scale, arranged in 23 four-layer macrocycles: three Kimi Delta Attention layers and one Multi-head Latent Attention layer per cycle. The KDA layers carry constant-size recurrent memory; the periodic MLA layers give back full softmax retrieval over the actual context, the thing a fixed-size state can't fully hold. Every layer after the first routes through a Mixture-of-Experts with 898 experts: two run on every token, and the router picks 16 more out of the remaining 896 for each one, so most of the model's expert parameters sit idle on any given token. The activation function is new too, called SiTU, replacing the usual SiLU-gated path into the down-projection. Without a fused kernel it runs nearly three times slower on its own; the model recoups that by pushing the experts through a compressed latent space, which nearly halves the total FLOPs.

## AttnRes

Ordinarily, a layer's input is the plain sum of the embedding and every earlier layer's output, weighted equally, so a layer with something important to add has to learn an increasingly large output just to move that sum at all, a pressure that destabilizes training as the stack gets deep. AttnRes replaces the equal-weighted sum with a learned query at each layer that attends back over earlier depth-wise representations and weighs them by relevance instead of by position, keeping a later layer's signal from being diluted in the accumulated stream. Run at every layer it would cost too much, so KimiK3 applies it once every 12 layers, eight such blocks across the 23 macrocycles; the extra attention step adds about 2% inference latency and buys a 1.25x compute advantage.

AttnRes and MLA end up solving the same problem from different directions. A KDA layer's state is constant in size and must eventually discard something; MLA retrieves what it needs from the token context, and AttnRes retrieves what it needs from earlier depth, neither one from anywhere the fixed-size recurrent state was ever holding it. A fixed-capacity memory always needs an eviction policy in the end. Every step from linear attention to AttnRes is a different answer to what gets evicted, and when, and who gets to decide.
