Everyone is renting the same brain now. A software travel agent answered a trip question with an exchange rate to one decimal place, a week's temperature, and museum hours. Specific, clean, useful-sounding. All of it invented. Search had returned nothing; the model filled the hole and handed its invention over as a fact it had looked up. Across 100 real sessions, response quality was 83.9%, but grounding in what the tools actually returned was 32.3%. The agent wrote beautifully and told the truth about a third of the time. A better model would not have caught this. The missing layer decides whether an answer was right and acts on the verdict. That layer is the whole distance between an AI that impresses people and an AI that gets paid. It is the cheapest line in the stack and the only one nobody can sell you, because it encodes your own definition of correct.

One company running agents in production changed no model, prompts, or human nudges across successive versions. It changed only the evals, and scores moved across every dimension. Its conclusion was blunt: evals should have been in the system on day one, not month nine. A thermometer tells you the room is cold. A thermostat turns the heat on. Most teams have a thermometer at best: a dashboard, a feeling, a Friday afternoon spent scrolling outputs and deciding the system seems worse. Eval engineering is the wiring from the reading to the furnace. One agent in a loop tries, inspects the return, and tries again; a graph runs independent work side by side. Evals add the return arrow, so the verdict changes what runs next. Loops, then graphs, then evals. The graph was the last upgrade that made you faster. The judge decides whether that speed was worth having. Twenty agents running at once, all reporting to one frozen judge, create twenty times as many places for a wrong answer to look finished. The model is a rental. The examiner is yours, and every failure you feed it stays there permanently.

You will build your first evaluation, get a number, look at it, and feel nothing happen. That feeling is correct. A number in a report has no path back to the run it measured. A score that never changes behavior is analytics. An eval that changes the next edge is engineering. Low context recall rejects a handoff; bad tool use retries or swaps a node; hallucination quarantines a branch; schema failure blocks an edge; compliance risk routes to human review; verified completion terminates the run. Each verdict is a routing decision. The judge should come from another model family. Its rubric should be one primary line: `Pass iff [the independently observable successful outcome]`. The judge handles semantic calls; plain code checks whether a test passed, a file exists, or state changed. The evaluation skill forbids scoring response length, keywords, citation count, exact phrasing, tool-call count, or similarity to a reference. Pinning and logging the judge version keeps scores comparable. An agent optimized against a familiar judge learns to look right rather than be right.

Tests you invent from imagination protect you from failures you already imagined. The expensive failures have timestamps in your production logs. The skill starts with 25 complete traces, no more, with good and bad behavior sitting next to each other: a finished normal request; a user-confirmed request; a correction or rephrase; a failed, empty, or repeated tool call; and an external timeout or rate limit. Each gets four lines: observed behavior, comparison, attribution, eval candidate. Attribution is where beginners lose a week. The same lookup twice with identical arguments is your loop; a 429 is the dependency's limit unless your agent should recover. One capability becomes a task folder whose instruction and environment are visible to the target agent, while the expected outcome, rubric, and judge credentials stay hidden. The trace records what the agent did, not what it should have done. The verifier gets one clearly correct and one plausible but wrong result, and the environment must not reveal the answer before the agent reaches the tool. Anything that costs money or writes to production gets simulated.

That workflow no longer requires a platform contract. In a blind test, two researchers took 100 production traces from a live voice agent, had an expert mark every failure, built a taxonomy of 39 labeled failures, hid the labels, and gave the same pile to each evaluation system. A coding agent reached 84.6% recall and 82.8% precision, above two dedicated platforms. Within four weeks, four vendors shipped their expertise as skills for coding agents already open in the terminal. The AWS kit's `evalkit init` lays out the evaluation folder, and `/evalkit.report` returns prioritized recommendations tied to locations in your code. The examiner is installed. Now the score has to reach the run.

Every pull request an agent opens lands in the same human queue. Once an eval can steer a run, it can steer that queue. Four signals are already available: deterministic guardrails, the recent eval trajectory for this agent version, its historical revert rate on this repository and class of change, and the sandbox outcome. Together they form a confidence score. Above a threshold the change merges itself; below it, a human gets the named failing signal. Three of the four are history or deterministic checks, and exactly one touches the model. Trust in an agent is an actuarial calculation. At one company, 19 of every 20 pull requests on a fully autonomous agent merge without human involvement. Yet 38 green tests once coexisted with a completely broken product. The loop must converge on the specification, not the score. The gate runs in shadow for at least four hours, stays closed when its verdict disagrees with a human verdict by more than 2%, and samples 1% to 5% of traces. The risky slice stays closed while the boring 80% opens.

A first suite has three measurements, not twelve: faithfulness to tool returns, tool-parameter accuracy, and response quality. The dataset type sets the unit: `final_response` for the answer, `single_step` for one decision, `trajectory` for the whole path, or `RAG` for retrieval. Scoring only the final response can hide a broken sequence. A useful suite holds out 300 to 800 cases and keeps 500 running in under five minutes; a suite longer than a coffee break stops being run. Its first five evals are an empty tool result that forces the agent to admit it has no number; a repeated call that fails a loop; a boundary refusal; a handoff-integrity check; and verified completion, where a real signal says done, never the agent's own word for it.

You can install one skill, build one eval today, and add another whenever something breaks.
