The Model Context Protocol (MCP) enables AI applications to extend their knowledge by establishing structured connections between an AI application (the host) and external services (the servers). When an AI application, such as Visual Studio Code, runs as the host, it utilizes internal components—the client—to maintain dedicated connections to multiple MCP servers, such as a local filesystem utility or a remote Sentry database. MCP servers define the core context data, and the protocol governs how this context is shared, irrespective of whether the server runs locally via STDIO transport or remotely over HTTP.

At its core, MCP is organized into two layers: the outer Transport layer, which manages communication details (like authentication and message framing), and the inner Data layer, which defines the standardized JSON-RPC 2.0 exchange for all primitives. The exchange is stateless, meaning every request must carry metadata detailing the client’s identity, the current protocol version, and its capabilities.

The communication begins with discovery. Clients first send a `server/discover` request to identify what the server supports. This handshake reveals the server's capabilities, telling the client which primitives are available, such as `tools`, `resources`, and `prompts`. These primitives define the three main ways context is shared: executable functions (`tools`), data sources (`resources`), or reusable interaction templates (`prompts`).

Once a client knows a server offers tools, it can perform a `tools/list` request to discover the server’s specific functionalities. This process allows the language model to build a comprehensive internal registry of available actions. The next step is execution: the client calls `tools/call` using the server's defined tool name and required input arguments, allowing the AI application to perform actions in the external world.

Crucially, MCP supports real-time updates via notifications. Because environments change—tools can be modified, or functionality can become temporarily unavailable—the connection must be kept current. Clients can subscribe to changes, opening a long-lived notification stream. When the server state changes, it sends a notification message, allowing the AI application to automatically refresh its tool registry and ensure that ongoing conversations always have access to the most accurate set of capabilities.
