title: The parts that remember
byline: The Editors
---

A server can pause a request, return questions with a `requestState`, and let any instance resume when the answers arrive. The work survives because its state travels with the request instead of hiding in a connection.

That small design carries further than MCP. An eval earns its keep when a failed result changes the next edge. An empty search should stop an agent from inventing museum hours. Planning earns leverage when a decision made before coding prevents expensive rework. In each case, a record becomes useful only when the next action can read it.

The intrusion was the harsher test of the same idea. Credentials, tokens, and thousands of probes moved through ordinary services, but the records did not join. Successful paths vanished among dead ones until investigators reconstructed events across layers. The bridge between those cases is operational: state must travel far enough to change what happens next, whether the next step is a retry, a review, or a shutdown.

A model may forget, a network may reconnect, and a team may replace its tools. The unfinished work still has somewhere to go, carrying with it the evidence that may finally tell the system to stop.
