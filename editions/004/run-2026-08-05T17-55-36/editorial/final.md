title: The Ten-Minute Question
byline: The Editors
---

The code can arrive in twenty minutes while the feature waits.

Before AI, coding took only 25–50% of the time to ship a feature. People aligned on what to build, reviewed the result, reworked it, and tested it. An agent that writes code faster reaches those queues sooner.

A principal engineer can spend an afternoon specifying a task and still leave a ten percent chance of significant rework. A two-sentence prompt leaves roughly half the work exposed to rework. The useful question is where the next ten minutes will remove the most expected pain. The engineer should answer that question, then stop before planning becomes a second project.

When an unanswered product question blocks a technical choice, she may need to zoom in and settle the technical detail. When the detail can wait, more planning only delays the prompt.

The feature moves when the engineer answers the question whose wrong answer would force the most rework.
