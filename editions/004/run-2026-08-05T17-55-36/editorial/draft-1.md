title: The Ten-Minute Question
byline: The Editors
---

A feature can spend twenty minutes in the editor and still take a week to ship.

The code is often the smallest part of the work. Before it, people decide what to build and how it should fit the system. After it, they review, rework, test, and verify. An agent that writes code faster reaches the same queues sooner.

The useful question is where a mistake would hurt. A loose prompt may leave half the expected pain in place. A careful specification lowers that risk, but writing one can consume the time saved. The engineer's job is to spend attention where it removes the most expensive uncertainty, then stop before planning becomes a second project.

That changes the shape of expertise. Knowing the codebase still matters, but so does knowing which unanswered question deserves ten minutes now and which can wait until the next level down. The factory moves when its bottleneck moves. Sometimes the bottleneck is a blank file. Often it is the decision before it.
