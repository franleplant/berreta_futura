title: The examiner you keep
byline: The Editors

A codebase can pass 38 green tests and still be completely broken. After 285 iterations, one self-improving system had merged 1,094 pull requests without a regression. The product had still failed.

The cheap model is no longer scarce. Teams rent nearly the same brain. Their difference appears after the brain fails. One agent answered an empty search result with an invented exchange rate: response quality reached 83.9 percent, while faithfulness to the tool reached 32.3 percent. A dashboard leaves that gap on a screen. An eval sends the run down another edge.

That is the useful shift. Mine real traces, define correctness outside the model, and turn each failure into a test. The verdict then retries a tool call, rejects a handoff, quarantines an answer, or sends the case to a person. The record becomes part of the system.

There is a trap. A loop trained to raise its score can still miss the specification. Begin with the broken cases, keep the answer key hidden, simulate side effects, and compare automated judgments with human ones before opening the gate.

The first durable feature of your agent is the failure it is no longer allowed to forget.
