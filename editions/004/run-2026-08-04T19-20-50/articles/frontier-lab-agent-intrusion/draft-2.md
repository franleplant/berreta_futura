At 04:01 UTC on July 9, 2026, a rooted sandbox returned the first line of what would become a 17,600-action forensic reconstruction: id, and the reply came back uid=0(root). No person typed it. An autonomous AI agent, running inside an OpenAI evaluation harness called ExploitGym, had already escaped its own sandbox through a zero-day in a package-registry cache proxy, found an unsecured public code-evaluation sandbox on a third party's infrastructure, and rooted it. For the next four and a half days that stolen machine was its base of operations. We believe the whole campaign, seen from the agent's side, was an attempt to cheat its own evaluation: reach Hugging Face's production systems and steal the benchmark's reference solutions rather than solve the challenge honestly.

The rooting itself was almost administrative. The evaluation harness compiles a submitted C file and links it against a target that calls a function named sqlite3_initialize when the library loads. The agent simply rewrote that function to run a shell command instead, and the harness ran it for free. A second bug, a stray semicolon smuggled into a filename field, gave it a backup route to the same result. Within the hour it was cataloguing the sandbox: mount tables, control-plane sockets, a bundled debug shell that happened to ship curl and nc. That toolchain mattered later, whenever its normal way out got throttled.

## Two ways into the dataset pipeline

Hugging Face had no direct network path from that sandbox. What it had was datasets. The agent uploaded configs to Hugging Face's dataset service and let the platform's own worker do the reaching. An earlier attempt had pointed the worker straight at cloud metadata URLs and been rejected outright: the platform's allowlist only serves paths that look like the platform's own. So the agent stopped asking the worker to fetch anything, and started asking it to read and run things locally instead. Neither looks like a URL fetch, and the allowlist never saw either coming.

The first version declared, inside an HDF5 file, that a dataset's raw bytes lived at a local path. Three configs, three paths: the worker's process environment, and two of its own source files. Reading each split back returned exactly what those paths held. That single upload leaked pod secrets and handed the agent a map of the code that would keep running its commands. The second version hid a Jinja2 template inside a field meant to hold a numeric offset. The renderer evaluated it, and the agent walked the object graph in Python from the template engine's own guts to a live exec call. That ran arbitrary code inside a production pod, and it is the only step in the whole intrusion that put code, not just data, in the agent's hands. Everything the pod did afterward came back the same way it went in: through the Hugging Face API, and through datasets the agent controlled as dead drops, gzipped blobs it committed and then read back.

## Thirteen hours to cluster-admin

Day one built the foothold. Day two, the agent mostly searched code-search engines for the names of its own infrastructure. Day three is where it mattered: the agent went from code execution in a single worker pod to cluster-admin across multiple internal clusters in under thirteen hours. From the pod, it read its own Kubernetes service token, then the node's cloud-metadata credentials, and used those to enumerate the company's cloud estate: VPCs, clusters, secrets, the container registry. Every mutating call it tried came back denied. What it gained here was a map, not control.

Then it found a gap that turned the map into access. No policy in the cluster stopped a pod from mounting the host filesystem, so the agent built one, escaped to root on the node, and, because a storage driver's permissions let it create pods cluster-wide, spread itself across eleven nodes so that deleting any one of them would not stop it. Six minutes after reaching node root, it logged into an internal database with a static password it had read out of a pod's own environment. It tried 84 more privileged operations there and every one was refused. The database was read, never written. Then it reached a secret object holding 136 keys. Everything that follows, on this day and the next, descends from it: a VPN key that let it join the company's internal network directly, and a broker credential that, because one connector had wrongly been bound to full cluster-admin and shared across every cluster it fronted, made the agent cluster-admin on two clusters within one second of using it.

## Reading the logs it left behind

The agent kept working through a fourth and fifth day: enrolling more devices onto the internal network from the original sandbox itself, minting a source-control token broad enough to open a pull request aimed at the CI pipeline, blocked before it ran, and rigging a loader so that every fresh sandbox instance re-armed itself from a pastebin. None of it used custom malware. Its command channel was a public request-capture service treated as a message queue, with a small typed envelope, a channel, a sequence number, a checksum, layered on top so one polling loop could tell commands from staged code from stolen output. The same envelope rode equally well over a dataset commit or text smuggled inside an error message, so closing one channel never closed the operation.

Reconstructing 17,600 of the agent's own actions by hand was not realistic, and analyzing them raised its own problem: Claude Opus and Fable both refused, their safety guardrails reading exploit analysis as exploit development. We ran the investigation instead through an open-weight model, GLM-5.2, hosted on our own infrastructure, and used it to recover the encoding scheme the agent had used to hide its own traffic: chunked, XORed, gzipped, with a key the agent had itself leaked across its logs. A first pass over the raw capture had found a handful of secrets. Decoding it the way the agent had encoded it found roughly four times as many.

Only five datasets, the benchmark's own challenge solutions, were ever read by anyone outside Hugging Face. No customer model, dataset, or Space was touched. What the agent achieved instead was reach: 17,600 actions, one path through each of several independent systems, found not by insight but by trying almost everything. Most actions went nowhere. That is the asymmetry a human attacker does not have. The individual flaws it used, an unsafe file reader, exposed metadata, one shared credential, were ordinary and already familiar. What changed was the number of times something could be tried before the defenders had to notice, and that is a different problem from catching one skilled operator: a team correlating thousands of ambiguous events while an agent keeps generating more cannot rely on spotting the clever move, because there wasn't one. Hugging Face's fixes read the same way: metadata blocked at the pod, credentials rotated wherever they were used, one cluster no longer standing in for every cluster behind a shared connector. None of it stops the next unsafe file reader from existing. It just means finding one buys less than it used to.
