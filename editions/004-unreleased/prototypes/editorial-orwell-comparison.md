## Orwell-based rewrite

**Label:** EDITORIAL: ORIGINAL EDITOR TEXT

**Title:** Intelligence Needs Surroundings

**Byline:** The Editors

A model never works alone. A protocol, a runtime, tools, review rules, an evaluation loop, and a network of assumptions surround it. Together they set what the model can see and do. They also decide whether anyone catches its mistakes.

This edition studies that system at six scales. A frontier agent crosses infrastructure at machine speed. An evaluation layer turns attractive output into routing decisions. A software factory looks for the little planning that removes most expected rework. A model architecture trades pairwise attention for recurrent state, selective retrieval, and sparse capacity. MCP draws the line between an AI application and the context it can reach. It then changes that line so it can work like ordinary stateless web infrastructure.

The model still matters, but it no longer explains enough on its own. Model capability becomes useful only when the system can show its state, preserve evidence, limit action, and change course. The machinery around the model is not support work. It is the product.

## Rule-by-rule audit

1. **Avoid clichés and familiar figures of speech.** Replaced the personifying arrival construction with the literal claim that a model does not work alone. Retained “draws the line” because it makes an abstract boundary easier to grasp.
2. **Prefer short, common words.** Changed “policy” to “rules,” “notices when it is wrong” to “catches its mistakes,” “adequate unit of analysis” to “explains enough on its own,” “expose” to “show,” and “constrain” to “limit.”
3. **Cut every word that does no work.** Removed “a set of,” “simply,” and repeated framing. Split dense sentences where the shorter form makes each claim easier to follow.
4. **Use the active voice.** The protocol, runtime, tools, rules, loop, and network now “surround” the model. The system “sets,” “decides,” “shows,” “preserves,” “limits,” and “changes.”
5. **Prefer plain English to jargon.** Removed “unit of analysis” and simplified the framing around the system. Kept “runtime,” “routing decisions,” “recurrent state,” “selective retrieval,” “sparse capacity,” and “stateless web infrastructure” because they name the edition’s technical subjects.
6. **Break any rule when breaking it makes the writing clearer.** Kept those technical terms and the repeated closing sentence “It is the product.” Precision and emphasis matter more here than replacing every specialized term or merging the final two sentences.
